# Sunspark Rumble construction and validation rules

- Read `design/surface-construction.md` before changing geometry, terrain, surface decoration, batching or collision visuals.
- One rendered finish owns each structural surface. Never leave a visible slab, terrain face or duplicate finish coplanar with it. Preserve gameplay heights by separating collision proxies from recessed rendered backing.
- Build coastal roofs, boardwalks and shed floors with `coastalLayeredDeck`. It preserves the gameplay top and uses `SURFACE_CLEARANCE` (0.02 metres) for the rendered backing. Do not assemble a visible slab plus finish independently.
- Register new layered structural finishes with `registerSurfaceLayer`; supply samples across the finish in its parent's coordinates. Include added assemblies in the real-scene audit. Do not remove samples, hide visible content from the audit or weaken its separation threshold to make a failure pass.
- Door jambs and headers need exposed front/back and narrow reveal checks through `registerJoineryFaces`, including samples near their joints. Posts must meet headers without overlapping coplanar faces; recess wall end grain behind the lining, continue opaque backing above the opening, and preserve the collision opening. Run `npm run test:beams:browser` for walk-by views of all nine open frames in all presets, alongside the surface gate.
- Floors must clear the authoritative sampled terrain across their entire footprint, not only at their centre. Grade the underlying heightfield when needed, preserving accessible entrances and shared rendering/collision heights; the surface gate also checks terrain clearance.
- Do not conceal structural overlap with `renderOrder`, disabled depth testing/writing, transparency, camera clipping changes or polygon offset. A deliberate decal may use an appropriate documented technique and needs its own render check.
- When changing a renderer feature that affects material shader defines (such as shadow mode), invalidate affected cached material programs and verify the actual compiled program after a preset switch. Keep the browser shadow-mode regression.
- New or repositioned collidable rocks require full-body falling, jumping, slope-contact and embedded-recovery tests for players and bots. Matching mesh raycasts alone does not prove locomotion works. Run the rock-trapping regressions; preserve ordinary step, ramp, roof and gap traversal.
- Run `npm run test:surfaces` after geometry/batching changes. Before shipping such a change, also run the relevant gameplay tests and `npm run test:surfaces:browser` with the local server and current QA build. Inspect elevated and grazing camera views in all three presets. Keep the existing terrain/floor, ramp, crate and shadow regressions.
- `npm run package:release` runs the real-scene surface audit before copying release files. A failed surface gate blocks packaging. Record before-failure and after-pass evidence when repairing a regression.

These checks cover registered opaque structural layers. They are not a universal test for shadow shimmer, texture aliasing, animated foliage or every possible GPU/depth configuration; investigate other flicker by its actual cause.
